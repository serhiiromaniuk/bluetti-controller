## Escape hatches
- If a step fails 3 times: stop, log the blocker, set status: blocked, emit `<<LOOP:BLOCKED>>`. A handshake that never completes on hardware is this case (Q3: no sidecar without the owner).
- If a destructive / secret-touching / irreversible external action is required: stop and hand to a human. This covers BLE pairing/bonding requests, any 0x06/0x10 frame, `control.enabled = true`, `sudo`/BlueZ settings/adapter reset, a station firmware update, and a key or real MAC/SN that reached a pushed commit (a history rewrite).
- If a source turns out not MIT/Apache, or only GPL code covers a needed part: do not port it; `<<LOOP:BLOCKED>>`.
- If a hardware step finds no station (out of range, app connected): log it and retry later; it counts toward the 3-failure hatch.
- Gate failures — `src/protocol/` coverage < 80%, or an acceptance run < 19/20: `<<LOOP:GATE_FAILED>>`. Fix the work, never the threshold; a wrong metric goes only via the falsified-metric path (AGENTS.md §6).
